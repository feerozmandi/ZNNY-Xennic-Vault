# فایل‌های موردنیاز دستیار وبسایت برای بازبینی

این فهرست مربوط به ZIP نسخهٔ `1.1.0` است؛ بسته شامل ۴۰ فایل است، همگی غیرمحرمانه و بدون runtime Secret. **درخواست از دستیار:** بازبینی فقط ایستا روی commit مبنا؛ هیچ دستوری روی VPS، gate فعال یا حساب OAuth اجرا نشود.

## اولویت ۱ — Compose پایه، overlay و متغیرها

- `compose.preview.yml` — کپی byte-for-byte از base Compose وبسایت در commit مبنا؛ فقط برای بازبینی. در اجرا باید همان فایل از checkout سایت استفاده شود تا build context درست باشد.
- `compose.payload-lab.override.yml` — overlay مستقل بر Compose پایه؛ بررسی `!reset`, internal project network, project isolation, named-volume namespace, حذف publish اپ و loopback-only Caddy.
- `.env.preview.example` — نمونهٔ placeholder-only برای متغیرهای Compose؛ هرگز source یا به Compose ندهید. فایل خصوصی synthetic در آینده فقط با helper ساخته می‌شود.
- `prepare_payload_lab_env.py` — فقط در صورت تأیید، env تصادفی Postgres/Payload را خارج از بسته و mode `0600` می‌سازد؛ در Arena یا روی رایانهٔ مالک اجرا نشده است.

## اولویت ۲ — پیکربندی و ترتیب درخواست

- `Caddyfile` — candidate برای TLS عمومی/ACME؛ بررسی دامنه، issuer، port 443، خاموش‌بودن redirect و HTTP-01، و امکان renewal با محدودیت شبکهٔ فعلی.
- `Caddyfile.payload.lab`, `routes.caddy`, `oauth-gateway.caddy`, `upstream.caddy` — Caddy روی loopback در Compose، دسترسی به `gate:4180` و `app:3000`، حفاظت همهٔ مسیرها ازجمله `/api/graphql`, حفظ Payload Bearer/Cookie، حذف فقط Cookie gate و پاسخ callback عمومی را بررسی کنید.
- `Caddyfile.lab`, `fixture.py` — fixture مستقل قدیمی/مصنوعی، بدون اپلیکیشن واقعی.
- `check_caddy_config.py`, `test_caddy_mock.py` — checker و آزمون Caddy synthetic؛ Caddy binary در محیط بسته نبود و آزمون اجرا نشده است.

## سؤال‌های باز برای دستیار وبسایت

لطفاً برای هر نکته یکی از «تأیید»، «نیازمند اصلاح» یا «نامعلوم» را ثبت کنید:

1. آیا Caddyfileهای candidate روی Caddy `2.11.7` قابل parse هستند و ترتیب matcherها/`handle_response` دقیقاً همان رفتار موردنظر را دارد؟
2. آیا حذف Cookie با regex در `upstream.caddy` در برابر تمام layoutهای Cookie/چند header قابل قبول است، بدون حذف Payload token یا عبور gate token؟
3. آیا مسیر واقعی `/api/graphql` از matcher `/api/*` با همان `forward_auth` حفاظت می‌شود؟
4. آیا proxy اجازهٔ Bearer برای Payload می‌دهد ولی آن را به OAuth2 Proxy نمی‌فرستد؟ آیا CORS/CSRF و `Origin` با `PREVIEW_ORIGIN` دقیق سازگارند؟
5. آیا تبدیل callback `4xx→403`, `5xx→500` به‌اندازهٔ کافی جزئیات provider را پنهان می‌کند و درعین‌حال دسته‌بندی عملیاتی را برای ادمین ممکن می‌گذارد؟
6. آیا `!reset []` و network `internal: true` برای Compose حداقل v2.24.4 صحیح‌اند و project/volume/network separation در ترکیب فایل‌ها معتبر است؟
7. آیا `Payload 3.91.0` در commit مبنا همچنان رفتار موردانتظار routeهای first-register/login/logout و cookie را دارد؟
8. آیا scope نهایی باید فقط `user:email` باشد، یا دسترسی org/team واقعاً نیاز است؟ **هیچ‌کدام پیش‌فرض یا تأییدشده فرض نشود؛ `read:org` فقط برای OAuth App محلی قدیمی مجاز بود.**
9. برای حساب دوم، چه نشانگرهای غیرمحرمانه‌ای باید سیاست حساب را از provider/API failure جدا کنند؟ لطفاً لاگ خام، Cookie یا توکن درخواست نخواهید.

## کارهایی که بازبین نباید انجام دهد

- هیچ فایل config را روی gate فعال اعمال یا reload نکند.
- OAuth/GitHub callback، account دوم، outage با نشست معتبر، DNS، VPS، عمومی‌کردن port یا Compose عملیاتی را اجرا نکند.
- scope `read:org` را به App نهایی تعمیم ندهد.
- Open Notebook، Hermes یا `[RAG-02]` را آغاز نکند؛ این‌ها خارج از preview و تحت قیود قبلی‌اند.

## خلاصهٔ تصمیم

این تحویل یک بازسازی قابل‌دانلود برای بررسی است، نه نسخهٔ آمادهٔ production. تنظیمات Caddy و OAuth2 Proxy candidate هستند؛ scope نهایی GitHub انتخاب/تأیید نشده و Compose OAuth قدیمی فقط مرجع `DO NOT RUN` است. تنها overlay پیشنهادی برای آزمون Payload از یک gate مصنوعی استفاده می‌کند و هیچ احراز هویت واقعی انجام نمی‌دهد. هیچ آزمایش تازه‌ای روی رایانهٔ مالک اجرا نشده است.

**اقدام بعدی:** فایل‌های فهرست‌شده در `FILES-FOR-WEBSITE-ASSISTANT.fa.md` را به دستیار وبسایت بدهید و منتظر بازبینی بمانید. پس از آن برنامهٔ آزمون یکپارچهٔ محدود با commit مبنا ارائه خواهد شد؛ اجرا فقط با تأیید صریح مالک.

## طرح Caddy در فایل‌های بسته

`Caddyfile` تنظیم candidate روی `https://preview.xennic.ir` را نشان می‌دهد و `routes.caddy` مسیرها را تعیین می‌کند. فایل `compose.preview.yml` داخل بسته کپی دقیق base Compose از website commit است؛ برای build واقعی در آینده باید از همان فایل داخل checkout سایت استفاده شود تا build context `.` به کد سایت اشاره کند.

- در overlay، Caddy به `gate:4180` برای auth و به `app:3000` برای Payload می‌رسد؛ این نام‌های DNS سرویسی از شبکهٔ اختصاصی همان Compose project هستند. Caddy فقط بعد از پاسخ مجاز از `/oauth2/auth`، upstream برنامه را reverse-proxy می‌کند.
- overlay یک network مختص project با `internal: true` می‌سازد و app، postgres، gate و Caddy را به آن وصل می‌کند؛ نام‌های سرویس `app`, `postgres`, `gate` روی همین شبکه resolve می‌شوند. این network egress را مسدود می‌کند؛ رفتار startup برنامه در چنین شبکه‌ای هنوز اجرا نشده است.
- Compose پایه app را روی `127.0.0.1:${PREVIEW_PORT:-3000}:3000` منتشر می‌کند؛ overlay با `ports: !reset []` آن port را حذف می‌کند. PostgreSQL و gate هیچ host portی ندارند. تنها port منتشرشدهٔ overlay، Caddy روی `127.0.0.1:443:443/tcp` است؛ هیچ bind عمومی تعریف نشده.
- `@api path /api /api/* /graphql /graphql/*` در `routes.caddy` شامل مسیر واقعی Payload GraphQL یعنی `/api/graphql` است. آن مسیر و بقیهٔ `/api/*` از `forward_auth` به `/oauth2/auth` عبور می‌کنند و در نبود gate، 401 می‌گیرند. UI در 401 به `/oauth2/sign_in` هدایت می‌شود.
- `/oauth2/*` فقط به gate می‌رود، نه به Payload. پاسخ callback از gate در `4xx` به پیام عمومی `403` و در `5xx` به پیام عمومی `500` تبدیل می‌شود؛ بدنه، هدرهای داخلی، Set-Cookie و جزئیات provider به کاربر پاس نمی‌شوند و Cache-Control برابر `no-store` است.
- هنگام فراخوانی gate، هدرهای `Authorization` و هدرهای هویت/forwarding ورودی حذف می‌شوند؛ Host/Proto/آدرس مبدأ از Caddy بازسازی می‌شوند.
- هنگام ارسال به Payload، `upstream.caddy` با regex فقط Cookie با نام `__Host-preview_gate` و chunkهای عددی `__Host-preview_gate_N` را از هدر Cookie حذف می‌کند؛ Cookieهای Payload و نامرتبط، Bearer Payload، `Origin` و Fetch Metadata باید حفظ شوند؛ هویت ارسالیِ جعل‌شده حذف می‌شود. این رفتار هدف config/test است و Caddy mock هنوز اجرا نشده.
- `.env.preview.example` فقط placeholderهای آشکار برای متغیرهای Compose دارد؛ فایل واقعی `.env` یا Secret در بسته نیست و نمونه را نباید source/اجرا کرد. `prepare_payload_lab_env.py` تنها پس از مجوز، مقادیر synthetic را خارج از بسته می‌سازد.
- `Caddyfile.lab` از TLS داخلی برای fixture محلی استفاده می‌کند؛ `Caddyfile.payload.lab` نیز TLS داخلی دارد و به نام میزبان preview محدود است. این‌ها TLS عمومی یا آزمون DNS نیستند.

این‌ها **تنظیمات فایل candidate** هستند، نه وضعیت gate فعال یا تنظیم نهایی تأییدشده. تا اجرای `caddy adapt --validate` با نسخهٔ موردنظر، parser اعتبارسنجی نشده است؛ هیچ config زنده‌ای خوانده/نصب/تغییر داده نشده است.

## طرح OAuth2 Proxy و محدودیت مجوز

- `oauth2-proxy.example.toml` یک template عمداً unapproved است: scope برابر `UNAPPROVED_DO_NOT_RUN` و `trusted_proxy_ips` placeholder است. این sentinel مانع فنی startup نیست؛ فایل را اجرا نکنید. parse شدن TOML به‌معنای پذیرفته‌شدن آن توسط OAuth2 Proxy نیست. Candidate دارای `github_users=["feerozmandi"]` (محدودکنندهٔ نام کاربری؛ `email_domains=["*"]` فقط filter ایمیل است)، listen داخلی `0.0.0.0:4180`، upstream ثابت `static://202`، cookie `__Host-preview_gate` با Secure/HttpOnly/Lax، expiry `4h` و refresh `0` است. این expiry با نمونهٔ local قبلی (`1m`) فرق دارد و مقدار ۴ساعته آزموده نشده است. عدم عبور Bearer به gate و تنظیمات دیگر هم فقط طرح بازبینی‌اند.
- `oauth2-proxy.lab.example.toml` به توپولوژی آزمایش قبلی اشاره می‌کند: `user:email read:org` و `172.29.251.2/32`. این مجوز فقط برای OAuth App محلیِ جداگانه‌ای بود که مالک برای آزمون مستقلش تأیید کرده بود؛ scope نهایی App معلوم/تأییدشده نیست و نشانی شبکه نیز به topology قدیمی وابسته است.
- `compose.oauth-lab.reference.yml` ثابت و دارای پورت `127.0.0.1:18443`، subnet `172.29.251.0/28` و project name ثابت است. آن را اجرا نکنید؛ احتمال برخورد با lab مالک وجود دارد.
- `prepare_lab_config.py` اجرا نشده است. در صورت استفادهٔ مجاز در آینده، ورودی Client ID/Secret را مخفی می‌گیرد و فایل خصوصی mode `0600` را خارج از بسته در home می‌سازد؛ هیچ Secretی را در آرشیو یا چت قرار نمی‌دهد. این helper مجوز اجرای آزمون فعلی نیست.

## Overlay و آزمون‌های تحویلی

`compose.payload-lab.override.yml` برای checkout وبسایت دقیقاً روی commit مبناست. project name اختصاصی `xennic-preview-gate-payload-lab` دارد و دستور Runbook نیز `-p` را صریح می‌کند تا volumeهای DB/media از stackهای دیگر جدا بمانند. network اختصاصی `internal: true`، app/Postgres/gate/Caddy را فقط در همان project به هم متصل می‌کند و egress خارجی را محدود می‌کند؛ app/DB host port publish ندارند. این طراحی host را به‌عنوان مرز امنیتی حذف نمی‌کند و رفتار آن در Docker واقعی اجرا نشده است. پورت برنامهٔ Payload در override پاک می‌شود؛ فقط Caddy روی `127.0.0.1:443` منتشر می‌شود. `gate_stub.py` فقط marker مصنوعی را می‌پذیرد؛ OAuth، GitHub، کاربر واقعی و امنیت identity را پیاده‌سازی نمی‌کند. image digestها تأییدنشده‌اند، پس overlay تا بررسی آن‌ها `DO NOT RUN` است. overlay روی هیچ ماشینی اجرا نشده است.

مجموعهٔ آزمون‌ها شامل این موارد است:

1. `test_caddy_mock.py` — آزمون loopback با Caddy و upstream/gate مصنوعی؛ routeها ازجمله `/api/graphql`، حذف Cookie نشست، حفظ Bearer/Cookie اپ، حذف هدر هویتی، پاسخ callback پاک‌شده و چند چیدمان Cookie را می‌سنجد. OAuth/GitHub و Payload server را اجرا نمی‌کند؛ Caddy binary در این محیط موجود نبود و آزمون اجرا نشده است.
2. `test_payload_extraction.mjs` — `extractJWT` واقعی از npm Payload 3.91.0 را با هدرهای مصنوعی می‌خواند؛ برنامهٔ کامل یا DB را اجرا نمی‌کند.
3. `provider-policy-test/` — متدهای سیاست GitHub از منبع ثابت OAuth2 Proxy v7.15.5 استخراج می‌شوند؛ HTTP/session plumbing تستی است. هدف آن تفکیک «پروفایل با موفقیت دریافت شد ولی login خارج از allowlist است» از «درخواست org/team/profile/email به API خطا داد» است؛ callback یا login GitHub واقعی را اجرا نمی‌کند.
4. `test_payload_caddy.mjs` — آزمون یکپارچهٔ پیشنهادی برای Payload واقعی روی DB/media جدا و Caddy محلی، با gate مصنوعی و فقط پس از بازبینی/تأیید؛ هنوز اجرا نشده است.
5. `test_payload_browser.js` — آزمون اختیاری DevTools، فقط برای همان overlay مصنوعی؛ پیش‌فرض اجرا نمی‌شود.
6. `check_caddy_config.py` — `caddy adapt --validate` را برای configها مطالبه می‌کند، اما در محیط تهیهٔ این بسته Caddy نصب نبود و checker اجرا نشده است.

وضعیت اجرای دقیق را در `VALIDATION.fa.md` ببینید. نتیجهٔ آزمون‌های بازسازی‌شده را با نتیجهٔ بستهٔ گمشدهٔ قبلی اشتباه نگیرید.

## نسخه‌ها و digestها

نسخه‌های image در YAML به‌همراه مقادیر digest نوشته شده‌اند، اما دسترسی به registryهای Docker Hub/Quay در محیط بستهٔ تهیه موجود نبود؛ بنابراین digestهای image **به‌صورت مستقل راستی‌آزمایی نشده‌اند** و نباید زنجیرهٔ provenance تلقی شوند. Payload `3.91.0` از npm registry دریافت و `extractJWT` همان tarball آزموده شد؛ SRI/هاش در `VERSIONS-DIGESTS.fa.md` درج شده است. منبع `github.go` از tag `v7.15.5` دریافت و SHA256 بررسی شده است. Node و Postgres در Compose/Dockerfile فقط با tag هستند و digest pin ندارند.

## یافته‌های قبلی که بازتکرار نشده‌اند

نتایج زیر از گزارش‌های آزمایش قبلی مالک حفظ شده‌اند، اما فایل‌های بستهٔ قبلی غایب‌اند و آزمون‌های جاری نیستند:

- ورود مالک با OAuth App محلی پس از درخواست scope محلی `user:email read:org` گزارش شد؛ این scope برای App نهایی تأیید نیست.
- دادهٔ مصنوعی نشان داد Bearer/Cookie Payload حفظ و هدر هویتی جعلی حذف شده است.
- حساب دوم به fixture نرسید و callback `500 missing github user` گزارش شد. **علت معلوم نیست**؛ این مشاهده به‌تنهایی رد allowlist را از شکست provider/API جدا نمی‌کند.
- منقضی‌شدن نشست در حدود ۷۵ ثانیه، logout عادی و اعتبارسنجی مجدد 401 گزارش شد؛ replay نشست قدیمی پس از signout همچنان 200 بود.
- قطع gate فقط بدون نشست معتبر آزموده شد. آزمون outage با نشست معتبر صریحاً خارج از دامنه است و بدون مجوز تازه ممنوع می‌ماند.
- چند مسیر نمونه گزارش شده‌اند، اما پوشش همهٔ routeها ثابت نیست. CI سایت روی commit مبنا گزارش موفق داشت، اما proxy gate واقعی را اجرا نمی‌کند.

هیچ‌یک از موارد بالا روی فایل‌های بازسازی‌شده یا gate زنده در این مرحله دوباره اجرا نشده‌اند.

## تفکیک حساب دوم: قاعدهٔ گزارش

# Runbook مرحله‌ای — فقط پس از بازبینی و مجوز

## وضعیت توقف فعلی

**فعلاً هیچ مرحلهٔ اجرایی روی رایانهٔ مالک مجاز نیست.** این Runbook برای بازبینی است؛ ابتدا بسته به دستیار وبسایت داده شود. پس از دریافت نظر دستیار، برنامهٔ آزمون یکپارچهٔ محدود با مبنای commit در گزارش ارائه می‌شود. اجرای آن فقط با تأیید صریح مالک مجاز است.

هیچ دستور این سند را روی VPS، gate فعال، DNS یا Compose عملیاتی اجرا نکنید. فایل `compose.oauth-lab.reference.yml` را اجرا نکنید. آزمون outage با نشست معتبر در هیچ مرحله‌ای گنجانده نشده است. فرمان‌ها برای Bash/POSIX نوشته شده‌اند؛ در Windows معادل‌سازی/WSL را بدون بازبینی مجزا اجرا نکنید.

## مرحلهٔ صفر — کنترل بسته، بدون اجرای سرویس

پس از دریافت ZIP و استخراج آن، در ریشهٔ بسته:

```sh
sha256sum -c SHA256SUMS
python3 verify_bundle.py
```

Checksum ZIP را جداگانه با فایل sidecar مقایسه کنید. سپس فایل‌های `README.fa.md`، `REVIEW-REPORT.fa.md`، `CHANGELOG.fa.md` و `FILES-FOR-WEBSITE-ASSISTANT.fa.md` را بازبینی کنید. این مرحله فقط خواندنی است.

## مرحلهٔ یک — پیش‌نیاز/هویت کد (پس از بازبینی)

در checkout مستقل وبسایت، فقط commit مبنا را تأیید کنید؛ روی `dev`، `main` یا شاخهٔ عملیاتی جابه‌جا نشوید و هیچ فایل سایت را تغییر ندهید:

```sh
git -C /path/to/xennic-website rev-parse HEAD
```

خروجی مورد انتظار: `418de2b5b3a272e79a824ccde5411dc25f1002cc`. اگر checkout متفاوت است، توقف کنید. برای آزمون provider به Go 1.23+، برای parser به Node 22 و Payload 3.91.0، و برای Caddy mock/parser به Caddy 2.11.7 دقیق نیاز است. برای Compose overlay نسخهٔ Docker Compose v2.24.4+ لازم است. اگر هر نسخه یا فایل checkout متفاوت است، آزمون را اجرا نکنید.

## مرحلهٔ دو — آزمون‌های بی‌سرویس (پس از بازبینی)

این دستورات هیچ Docker service یا پورت عمومی را راه‌اندازی نمی‌کنند؛ با این حال روی دستگاه مالک، آن‌ها را پیش از بازبینی اجرا نکنید.

```sh
python3 - <<'PY'
from pathlib import Path
for name in ['check_caddy_config.py','test_caddy_mock.py','fixture.py','gate_stub.py','prepare_lab_config.py','prepare_payload_lab_env.py','provider-policy-test/generate.py']:
    compile(Path(name).read_text(), name, 'exec')
print('PASS Python syntax (in-memory; no __pycache__ written)')
PY
node --check test_payload_extraction.mjs
node --check test_payload_caddy.mjs
node --check test_payload_browser.js
python3 provider-policy-test/generate.py
(cd provider-policy-test && go test ./...)
```

`prepare_lab_config.py` و `prepare_payload_lab_env.py` **جزو این مرحله نیستند**؛ این دو فایل خصوصی خارج از بسته می‌سازند و فقط در مرحلهٔ مربوط، پس از تأیید، اجرا شوند. `generate.py` منبع ثابت را با SHA256 می‌سنجد و فایل Go تولیدشده را به‌روز می‌کند؛ پس از آن `python3 verify_bundle.py` را دوباره اجرا کنید تا تغییر ناخواستهٔ بسته دیده شود.

فقط دادهٔ مصنوعی استفاده می‌شود. اگر `node_modules/payload/package.json` نسخهٔ `3.91.0` نیست یا import شکست خورد، توقف کنید؛ پکیج دیگری را نصب/به‌روزرسانی نکنید تا برنامه اصلاح شود.

## مرحلهٔ سه — آزمون Caddy با mock loopback (فقط پس از مجوز صریح)

این آزمون Caddy 2.11.7 را روی پورت تصادفی `127.0.0.1` اجرا می‌کند و دو mock محلی دارد؛ OAuth2 Proxy، DNS، VPS و Payload واقعی ندارد. قبل از اجرا مطمئن شوید Caddy binary همان نسخه است و برای اجرای کوتاه‌مدت مجوز دارید:

```sh
CADDY_BIN=/path/to/caddy-2.11.7 python3 test_caddy_mock.py
CADDY_BIN=/path/to/caddy-2.11.7 python3 check_caddy_config.py
```

فرایند mock خودکار متوقف می‌شود. اگر Caddy خروج کرد، port درگیر بود یا parser خطا داد، آزمون را متوقف کنید؛ پورت/تنظیم live را تغییر ندهید. فقط ردهٔ نتیجه و نام آزمون را گزارش کنید، نه logهای خام.

## مرحلهٔ چهار — Payload واقعی با gate مصنوعی (فقط پس از بازبینی دستیار وبسایت و تأیید مالک)

این مرحله برنامهٔ پیشنهادی است، نه مجوز کنونی. فقط روی checkout مستقل وبسایت با commit دقیق اجرا شود؛ هیچ OAuth، GitHub واقعی، DNS، میزبان عمومی، tunnel یا service فعال استفاده نمی‌شود. `compose.preview.yml` داخل بسته برای بازبینی است؛ دستور build باید از `compose.preview.yml` داخل checkout استفاده کند تا context `.` به کد سایت دقیق برسد. اگر هر پیش‌شرط نامعلوم است، متوقف شوید.

۱. در ریشهٔ checkout، موجودبودن `compose.preview.yml` و آزادبودن `127.0.0.1:443` را بررسی کنید. هیچ سرویسی را برای آزادکردن پورت متوقف نکنید. اگر پورت درگیر است، **توقف**؛ این بسته برای تغییر پورت بازبینی نشده است.

۲. مطمئن شوید پروژه‌ای با نام `xennic-preview-gate-payload-lab`، یا volumeهای آن، از قبل وجود ندارد. در این بررسی فقط فهرست را ببینید؛ data volume را باز نکنید:

```sh
docker compose ls --all
docker volume ls --filter label=com.docker.compose.project=xennic-preview-gate-payload-lab
```

اگر پروژه یا volume از قبل وجود دارد، آن را reuse یا پاک نکنید. فقط پس از بررسی مالک، project name تازهٔ یکتا و برنامهٔ جداگانه لازم است.

۳. فقط پس از مجوز، فایل env مصنوعی بسازید:

```sh
python3 /path/to/bundle/prepare_payload_lab_env.py
```

این دستور فایل `~/.config/xennic-preview-gate-delivery/payload-lab.env` را با mode `0600` می‌سازد؛ مقادیر random هستند و روی صفحه چاپ نمی‌شوند. آن را باز/ارسال/commit نکنید. فایل `.env.preview.example` داخل بسته فقط راهنماست؛ آن را source یا به Compose ندهید. فایل خصوصی فقط برای Postgres و Payload disposable است، نه OAuth.

۴. در ریشهٔ checkout، `BUNDLE` را به مسیر کامل پوشهٔ استخراج‌شده تنظیم کنید، سپس **فقط config را اعتبارسنجی کنید**. `LAB_DIR` باید در environment باشد؛ `--quiet` را حذف نکنید تا مقادیر env چاپ نشوند:

```sh
BUNDLE=/absolute/path/to/xennic-preview-gate-delivery-2026-10-31-v1.1.0
ENV_FILE="$HOME/.config/xennic-preview-gate-delivery/payload-lab.env"
LAB_DIR="$BUNDLE" docker compose --env-file "$ENV_FILE" \
  -p xennic-preview-gate-payload-lab \
  -f compose.preview.yml -f "$BUNDLE/compose.payload-lab.override.yml" config --quiet
```

اگر Compose کمتر از v2.24.4 است، `!reset` را نشناخت، یا `config --quiet` خطا داد، **توقف**. `docker compose config` را بدون `--quiet` اجرا نکنید؛ ممکن است envهای محرمانه را چاپ کند.

۵. **شرط توقف الزامی پیش از `up`:** در این نسخه digestهای Caddy/Python فقط مقادیر ثبت‌شده‌اند و registry verification ندارند؛ Node/Postgres پایه نیز digest ندارند. تا زمانی که دستیار وبسایت/مالک imageها را از registry معتبر independently بررسی و نسخه/ digest صحیح را در patch بازبینی‌شده تثبیت نکرده‌اند، این مرحله را اجرا نکنید. پس از آن هم تأیید صریح مالک لازم است. هیچ tag یا digestی را خودسرانه در این بسته تغییر ندهید.

۶. پس از تحقق شرط بالا و تأیید مجدد، stack مصنوعی را بالا بیاورید:

```sh
LAB_DIR="$BUNDLE" docker compose --env-file "$ENV_FILE" \
  -p xennic-preview-gate-payload-lab \
  -f compose.preview.yml -f "$BUNDLE/compose.payload-lab.override.yml" up -d --build
```

هیچ host portی جز `127.0.0.1:443` منتشر نمی‌شود؛ app و Postgres port publish ندارند. هر چهار سرویس روی network اختصاصی project با `internal: true` هستند و network خروجی به اینترنت را محدود می‌کند؛ این موضوع egress و health/startup را نیازمند بررسی می‌گذارد. gate stub فقط در همان network داخلی است. Caddy از CA محلی خودش استفاده می‌کند. اگر خروجی `ps` پورت غیر-loopback/غیرمنتظره نشان داد، آزمون را متوقف کنید و چیزی را restart یا تغییر ندهید.

۷. فهرست port mapping را بررسی کنید. خروجی باید فقط `127.0.0.1:443->443/tcp` برای Caddy داشته باشد؛ اگر هر port دیگری منتشر شده یا bind به `0.0.0.0` است، فوراً توقف کنید:

```sh
LAB_DIR="$BUNDLE" docker compose --env-file "$ENV_FILE" -p xennic-preview-gate-payload-lab \
  -f compose.preview.yml -f "$BUNDLE/compose.payload-lab.override.yml" ps
```

۸. گواهی عمومی CA را فقط برای کلاینت تست به‌کار ببرید؛ هیچ private key را کپی نکنید. CA محلی Caddy داخل volume در `caddy:/data/caddy/pki/authorities/local/root.crt` است. پس از بالا آمدن Caddy می‌توان گواهی عمومی را به یک مسیر موقت بیرون از Git کپی کرد:

```sh
CID=$(LAB_DIR="$BUNDLE" docker compose --env-file "$ENV_FILE" -p xennic-preview-gate-payload-lab \
  -f compose.preview.yml -f "$BUNDLE/compose.payload-lab.override.yml" ps -q caddy)
test -n "$CID" || { echo 'Caddy container not found; stop.'; exit 1; }
docker cp "$CID:/data/caddy/pki/authorities/local/root.crt" "$HOME/.config/xennic-preview-gate-delivery/lab-root.crt"
```

فقط `root.crt` عمومی را کپی کنید، نه `root.key`. این آزمون Node با resolver داخلی خود فقط `127.0.0.1` را هدف می‌گیرد؛ نیازی به تغییر `/etc/hosts` یا DNS نیست. سپس:

```sh
LAB_CA_FILE="$HOME/.config/xennic-preview-gate-delivery/lab-root.crt" \
  node "$BUNDLE/test_payload_caddy.mjs"
```

آزمون فقط یک Staff مصنوعی در DB جدید می‌سازد؛ token/password چاپ نمی‌کند. اگر DB جدید نبود، درخواست ثبت اول شکست خورد، TLS اعتبارسنجی نشد یا status غیرمنتظره بود، آزمون را متوقف کنید. برای مرورگر، `test_payload_browser.js` اختیاری است و به host mapping و trust محلی نیاز دارد؛ در برنامهٔ محدود فعلی از آن صرف‌نظر کنید و CA را به trust store سیستم/مرورگر نصب نکنید.

## مرحلهٔ پنج — توقف و بازگشت

پس از آزمون، در همان checkout و با همان `-p`، `--env-file` و دو Compose file:

```sh
LAB_DIR="$BUNDLE" docker compose --env-file "$ENV_FILE" \
  -p xennic-preview-gate-payload-lab \
  -f compose.preview.yml -f "$BUNDLE/compose.payload-lab.override.yml" down
```

`down` بدون `-v` فقط containerها و network همین project یکتا را جمع می‌کند؛ named volumeها باقی می‌مانند تا هیچ داده‌ای بی‌اجازه حذف نشود. این Runbook هرگز `docker compose down -v`، `docker volume rm`، restart سرویس موجود، حذف volume، یا stop کردن سرویس دیگری را مجاز نمی‌کند. گواهی `lab-root.crt` یک فایل عمومی آزمایشی است و در صورت پایان نیاز می‌توان آن را از مسیر خصوصی آزمایش پاک کرد؛ این کار volume را لمس نمی‌کند.

در صورت توقف زودهنگام: ابتدا دستور `down` بالا را فقط برای همین project یکتا اجرا کنید؛ اگر نام project/containerها تطبیق ندارد، هیچ cleanup نکنید و از مالک سؤال کنید. سپس نتیجه را فقط در قالب «نام مرحله + PASS/FAIL/STOP + status code/دستهٔ خطا + زمان تقریبی» گزارش دهید. لاگ خام، Cookie، token، OAuth `code`، password و env file ارسال نشود.

## نتیجه‌هایی که از draft قبلی همین نشست حفظ شده‌اند

func (p *GitHubProvider) getOrgs(ctx context.Context, s *sessions.SessionState) error {

	type Organization struct {
		// Support for Github organizations
		// https://docs.github.com/en/rest/orgs/orgs#list-organizations-for-the-authenticated-user
		Login string `json:"login,omitempty"`
		// Support for Gitea organizations
		// https://docs.gitea.com/api/1.24/#tag/organization/operation/orgGetAll
		Name string `json:"name,omitempty"`
	}

	pn := 1
	for {
		params := url.Values{
			"per_page": {"100"},
			"page":     {strconv.Itoa(pn)},
		}

		endpoint := p.makeGitHubAPIEndpoint("/user/orgs", &params)

		var orgs []Organization
		err := requests.New(endpoint.String()).
			WithContext(ctx).
			WithHeaders(makeGitHubHeader(s.AccessToken)).
			Do().
			UnmarshalInto(&orgs)
		if err != nil {
			return err
		}

		if len(orgs) == 0 {
			break
		}

		for _, org := range orgs {
			var orgName string
			if len(org.Login) > 0 {
				orgName = org.Login
				logger.Printf("Member of Github Organization: %q", orgName)
			} else {
				orgName = org.Name
				logger.Printf("Member of Gitea Organization: %q", orgName)
			}

			s.Groups = append(s.Groups, orgName)
		}
		pn++
	}

	return nil
}

func (p *GitHubProvider) checkRestrictions(ctx context.Context, s *sessions.SessionState) error {
	// If a user is verified by username options, skip the following restrictions
	if ok, err := p.checkUserRestriction(ctx, s); err != nil || ok {
		return err
	}

	var err error
	switch {
	case p.Org != "" && p.Team != "":
		err = p.hasOrgAndTeam(s)
	case p.Org != "":
		err = p.hasOrg(s)
	case p.Team != "":
		err = p.hasTeam(s)
	}

	if err != nil {
		return err
	}

	if p.Org == "" && p.Repo != "" && p.Token == "" {
		// If we have a token we'll do the collaborator check
		return p.hasRepoAccess(ctx, s.AccessToken)
	}

	return nil
}

func (p *GitHubProvider) checkUserRestriction(ctx context.Context, s *sessions.SessionState) (bool, error) {
	if len(p.Users) == 0 {
		return false, nil
	}

	verifiedUser, err := p.hasUser(ctx, s.AccessToken)
	if err != nil {
		return verifiedUser, err
	}

	// org and repository options are not configured
	if !verifiedUser && p.Org == "" && p.Repo == "" {
		return false, errors.New("missing github user")
	}

	return verifiedUser, nil
}

func (p *GitHubProvider) hasUser(ctx context.Context, accessToken string) (bool, error) {
	// https://developer.github.com/v3/users/#get-the-authenticated-user

	var user struct {
		Login string `json:"login"`
		Email string `json:"email"`
	}

	endpoint := p.makeGitHubAPIEndpoint("/user", nil)

	err := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(accessToken)).
		Do().
		UnmarshalInto(&user)
	if err != nil {
		return false, err
	}

	if p.isVerifiedUser(user.Login) {
		return true, nil
	}
	return false, nil
}

func (p *GitHubProvider) isVerifiedUser(username string) bool {
	for _, u := range p.Users {
		if username == u {
			return true
		}
	}
	return false
}

func (p *GitHubProvider) getEmail(ctx context.Context, s *sessions.SessionState) error {

	var emails []struct {
		Email    string `json:"email"`
		Primary  bool   `json:"primary"`
		Verified bool   `json:"verified"`

		WithContext(ctx).
		WithHeaders(makeGitHubHeader(s.AccessToken)).
		Do().
		UnmarshalInto(&emails)

			}
		}
	}

	return nil
}

func (p *GitHubProvider) getUser(ctx context.Context, s *sessions.SessionState) error {
	var user struct {
		Login string `json:"login"`
		Email string `json:"email"`
	}

	endpoint := p.makeGitHubAPIEndpoint("/user", nil)

	err := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(s.AccessToken)).
		Do().
		UnmarshalInto(&user)

		return err
	}

	// Now that we have the username we can check collaborator status

		if ok, err := p.isCollaborator(ctx, user.Login, p.Token); err != nil || !ok {
			return err
		}
	}

	s.User = user.Login
	return nil
}

// This is not oauth2-proxy's production requests package.
package requests

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
)

type request struct {
	url     string
	ctx     context.Context
	headers http.Header
}
type result struct {
	resp *http.Response
	err  error
}

func New(url string) *request { return &request{url: url} }
func (r *request) WithContext(ctx context.Context) *request { r.ctx = ctx; return r }
func (r *request) WithHeaders(h http.Header) *request { r.headers = h; return r }
func (r *request) Do() *result {
	req, err := http.NewRequestWithContext(r.ctx, http.MethodGet, r.url, nil)
	if err != nil { return &result{err: err} }
	req.Header = r.headers
	resp, err := http.DefaultClient.Do(req)
	return &result{resp: resp, err: err}
}
func (r *result) UnmarshalInto(dst any) error {
	if r.err != nil { return r.err }
	defer r.resp.Body.Close()
	if r.resp.StatusCode != http.StatusOK { return fmt.Errorf("unexpected status %d", r.resp.StatusCode) }
	return json.NewDecoder(r.resp.Body).Decode(dst)
}

// NewGitHubProvider initiates a new GitHubProvider
func NewGitHubProvider(p *ProviderData, opts options.GitHubOptions) *GitHubProvider {
	p.setProviderDefaults(providerDefaults{
		name:        githubProviderName,
		loginURL:    githubDefaultLoginURL,
		redeemURL:   githubDefaultRedeemURL,
		profileURL:  nil,
		validateURL: githubDefaultValidateURL,
		scope:       githubDefaultScope,
	})

	provider := &GitHubProvider{ProviderData: p}

	provider.setOrgTeam(opts.Org, opts.Team)
	provider.setRepo(opts.Repo, opts.Token)
	provider.setUsers(opts.Users)
	return provider
}

func makeGitHubHeader(accessToken string) http.Header {
	// extra headers required by the GitHub API when making authenticated requests
	extraHeaders := map[string]string{
		acceptHeader: "application/vnd.github.v3+json",
	}
	return makeAuthorizationHeader(tokenTypeToken, accessToken, extraHeaders)
}

func (p *GitHubProvider) makeGitHubAPIEndpoint(endpoint string, params *url.Values) *url.URL {
	basePath := p.ValidateURL.Path

	re := regexp.MustCompile(`^/api/v\d+`)
	match := re.FindString(p.ValidateURL.Path)
	if match != "" {
		basePath = match
	}

	if params == nil {
		params = &url.Values{}
	}

	return &url.URL{
		Scheme:   p.ValidateURL.Scheme,
		Host:     p.ValidateURL.Host,
		Path:     path.Join(basePath, endpoint),
		RawQuery: params.Encode(),
	}
}

func (p *GitHubProvider) hasOrg(s *sessions.SessionState) error {
	// https://developer.github.com/v3/orgs/#list-your-organizations
	var orgs []string

	for _, group := range s.Groups {
		if !strings.Contains(group, ":") {
			orgs = append(orgs, group)
		}
	}

	presentOrgs := make([]string, 0, len(orgs))
	for _, org := range orgs {
		if p.Org == org {
			logger.Printf("Found Github Organization:%q", org)
			return nil
		}
		presentOrgs = append(presentOrgs, org)
	}

	logger.Printf("Missing Organization:%q in %v", p.Org, presentOrgs)
	return errors.New("user is missing required organization")
}

func (p *GitHubProvider) hasOrgAndTeam(s *sessions.SessionState) error {
	type orgTeam struct {
		Org  string `json:"org"`
		Team string `json:"team"`
	}

	var presentOrgTeams []orgTeam

	for _, group := range s.Groups {
		if strings.Contains(group, orgTeamSeparator) {
			ot := strings.Split(group, orgTeamSeparator)
			presentOrgTeams = append(presentOrgTeams, orgTeam{ot[0], ot[1]})
		}
	}

	var hasOrg bool

	presentOrgs := make(map[string]bool)
	var presentTeams []string

	for _, ot := range presentOrgTeams {
		presentOrgs[ot.Org] = true

		if strings.EqualFold(p.Org, ot.Org) {
			hasOrg = true

			teams := strings.Split(p.Team, ",")
			for _, team := range teams {
				if strings.EqualFold(strings.TrimSpace(team), ot.Team) {
					logger.Printf("Found Github Organization/Team:%q/%q", ot.Org, ot.Team)
					return nil
				}
			}
			presentTeams = append(presentTeams, ot.Team)
		}
	}

	if hasOrg {
		logger.Printf("Missing Team:%q from Org:%q in teams: %v", p.Team, p.Org, presentTeams)
		return errors.New("user is missing required team")
	}

	logger.Printf("Missing Organization:%q in %#v", p.Org, maps.Keys(presentOrgs))
	return errors.New("user is missing required organization")
}

func (p *GitHubProvider) hasTeam(s *sessions.SessionState) error {
	var teams []string

	for _, group := range s.Groups {
		if strings.Contains(group, orgTeamSeparator) {
			teams = append(teams, strings.TrimSpace(group))
		}
	}

	var presentTeams = make([]string, 0, len(teams))

	for _, ot := range teams {
		allowedTeams := strings.Split(p.Team, ",")
		for _, team := range allowedTeams {
			if !strings.Contains(team, orgTeamSeparator) {
				logger.Printf("Please use fully qualified team names (org:team-slug) if you omit the organisation. Current Team name: %s", team)
				return errors.New("team name is invalid")
			}

			if strings.EqualFold(strings.TrimSpace(team), ot) {
				logger.Printf("Found Github Organization/Team:%s", ot)
				return nil
			}
		}
		presentTeams = append(presentTeams, ot)
	}

	logger.Printf("Missing Team:%q in teams: %v", p.Team, presentTeams)
	return errors.New("user is missing required team")
}

func (p *GitHubProvider) hasRepoAccess(ctx context.Context, accessToken string) error {
	// https://developer.github.com/v3/repos/#get-a-repository

	type permissions struct {
		Pull bool `json:"pull"`
		Push bool `json:"push"`
	}

	type repository struct {
		Permissions permissions `json:"permissions"`
		Private     bool        `json:"private"`
	}

	endpoint := p.makeGitHubAPIEndpoint("/repos/"+p.Repo, nil)

	var repo repository
	err := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(accessToken)).
		Do().
		UnmarshalInto(&repo)

	if err != nil {
		return err
	}

	// Every user can implicitly pull from a public repo, so only grant access
	// if they have push access or the repo is private and they can pull
	if repo.Permissions.Push || (repo.Private && repo.Permissions.Pull) {
		return nil
	}

	return errors.New("user doesn't have repository access")
}

func (p *GitHubProvider) hasUser(ctx context.Context, accessToken string) (bool, error) {
	// https://developer.github.com/v3/users/#get-the-authenticated-user

	var user struct {
		Login string `json:"login"`
		Email string `json:"email"`
	}

	endpoint := p.makeGitHubAPIEndpoint("/user", nil)

	err := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(accessToken)).
		Do().
		UnmarshalInto(&user)
	if err != nil {
		return false, err
	}

	if p.isVerifiedUser(user.Login) {
		return true, nil
	}
	return false, nil
}

func (p *GitHubProvider) isCollaborator(ctx context.Context, username, accessToken string) (bool, error) {
	//https://developer.github.com/v3/repos/collaborators/#check-if-a-user-is-a-collaborator

	endpoint := p.makeGitHubAPIEndpoint("/repos/"+p.Repo+"/collaborators/"+username, nil)
	result := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(accessToken)).
		Do()
	if result.Error() != nil {
		return false, result.Error()
	}

	if result.StatusCode() != 204 {
		return false, fmt.Errorf("got %d from %q %s",
			result.StatusCode(), endpoint.String(), result.Body())
	}

	logger.Printf("got %d from %q %s", result.StatusCode(), endpoint.String(), result.Body())

	return true, nil
}

// getEmail updates the SessionState Email
func (p *GitHubProvider) getEmail(ctx context.Context, s *sessions.SessionState) error {

	var emails []struct {
		Email    string `json:"email"`
		Primary  bool   `json:"primary"`
		Verified bool   `json:"verified"`
	}

	endpoint := p.makeGitHubAPIEndpoint("/user/emails", nil)

	err := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(s.AccessToken)).
		Do().
		UnmarshalInto(&emails)
	if err != nil {
		return err
	}

	for _, email := range emails {
		if email.Verified {
			if email.Primary {
				s.Email = email.Email
				return nil
			}
		}
	}

	return nil
}

// getUser updates the SessionState User
func (p *GitHubProvider) getUser(ctx context.Context, s *sessions.SessionState) error {
	var user struct {
		Login string `json:"login"`
		Email string `json:"email"`
	}

	endpoint := p.makeGitHubAPIEndpoint("/user", nil)

	err := requests.New(endpoint.String()).
		WithContext(ctx).
		WithHeaders(makeGitHubHeader(s.AccessToken)).
		Do().
		UnmarshalInto(&user)
	if err != nil {
		return err
	}

	// Now that we have the username we can check collaborator status
	if !p.isVerifiedUser(user.Login) && p.Org == "" && p.Repo != "" && p.Token != "" {
		if ok, err := p.isCollaborator(ctx, user.Login, p.Token); err != nil || !ok {
			return err
		}
	}

	s.User = user.Login
	return nil
}

func (p *GitHubProvider) isVerifiedUser(username string) bool {
	for _, u := range p.Users {
		if username == u {
			return true
		}
	}
	return false
}

func (p *GitHubProvider) checkRestrictions(ctx context.Context, s *sessions.SessionState) error {
	// If a user is verified by username options, skip the following restrictions
	if ok, err := p.checkUserRestriction(ctx, s); err != nil || ok {
		return err
	}

	var err error
	switch {
	case p.Org != "" && p.Team != "":
		err = p.hasOrgAndTeam(s)
	case p.Org != "":
		err = p.hasOrg(s)
	case p.Team != "":
		err = p.hasTeam(s)
	}

	if err != nil {
		return err
	}

	if p.Org == "" && p.Repo != "" && p.Token == "" {
		// If we have a token we'll do the collaborator check
		return p.hasRepoAccess(ctx, s.AccessToken)
	}

	return nil
}

func (p *GitHubProvider) checkUserRestriction(ctx context.Context, s *sessions.SessionState) (bool, error) {
	if len(p.Users) == 0 {
		return false, nil
	}

	verifiedUser, err := p.hasUser(ctx, s.AccessToken)
	if err != nil {
		return verifiedUser, err
	}

	// org and repository options are not configured
	if !verifiedUser && p.Org == "" && p.Repo == "" {
		return false, errors.New("missing github user")
	}

	return verifiedUser, nil
}

func (p *GitHubProvider) getOrgAndTeam(ctx context.Context, s *sessions.SessionState) error {
	err := p.getOrgs(ctx, s)
	if err != nil {
		return err
	}

	return p.getTeams(ctx, s)
}

func (p *GitHubProvider) getOrgs(ctx context.Context, s *sessions.SessionState) error {

	type Organization struct {
		// Support for Github organizations
		// https://docs.github.com/en/rest/orgs/orgs#list-organizations-for-the-authenticated-user
		Login string `json:"login,omitempty"`
		// Support for Gitea organizations
		// https://docs.gitea.com/api/1.24/#tag/organization/operation/orgGetAll
		Name string `json:"name,omitempty"`
	}

	pn := 1
	for {
		params := url.Values{
			"per_page": {"100"},
			"page":     {strconv.Itoa(pn)},
		}

		endpoint := p.makeGitHubAPIEndpoint("/user/orgs", &params)

		var orgs []Organization
		err := requests.New(endpoint.String()).
			WithContext(ctx).
			WithHeaders(makeGitHubHeader(s.AccessToken)).
			Do().
			UnmarshalInto(&orgs)
		if err != nil {
			return err
		}

		if len(orgs) == 0 {
			break
		}

		for _, org := range orgs {
			var orgName string
			if len(org.Login) > 0 {
				orgName = org.Login
				logger.Printf("Member of Github Organization: %q", orgName)
			} else {
				orgName = org.Name
				logger.Printf("Member of Gitea Organization: %q", orgName)
			}

			s.Groups = append(s.Groups, orgName)
		}
		pn++
	}

	return nil
}

func (p *GitHubProvider) getTeams(ctx context.Context, s *sessions.SessionState) error {
	// https://docs.github.com/en/rest/teams/teams?#list-user-teams
	type Team struct {
		Name string `json:"name"`
		Slug string `json:"slug"`
		Org  struct {
			Login string `json:"login"`
			Name  string `json:"name"`
		} `json:"organization"`
	}

	pn := 1
	for {
		params := url.Values{
			"per_page": {"100"},
			"page":     {strconv.Itoa(pn)},
		}

		endpoint := p.makeGitHubAPIEndpoint("/user/teams", &params)

		var teams []Team
		err := requests.New(endpoint.String()).
			WithContext(ctx).
			WithHeaders(makeGitHubHeader(s.AccessToken)).
			Do().
			UnmarshalInto(&teams)
		if err != nil {
			return err
		}

		if len(teams) == 0 {
			break
		}

		for _, team := range teams {
			var orgName, teamName string

			if len(team.Org.Login) > 0 {
				orgName = team.Org.Login
				teamName = team.Slug
				logger.Printf("Member of Github Organization/Team: %q/%q", orgName, teamName)
			} else {
				orgName = team.Org.Name
				teamName = team.Name
				logger.Printf("Member of Gitea Organization/Team: %q/%q", orgName, teamName)
			}

			s.Groups = append(s.Groups, fmt.Sprintf("%s%s%s", orgName, orgTeamSeparator, teamName))
		}

		pn++
	}

	return nil
}

def request(port, path, headers=None, multiple=None):
    conn = http.client.HTTPConnection('127.0.0.1', port, timeout=4)
    try:
        if multiple is not None:
            conn.putrequest('GET', path)
            for name, value in multiple: conn.putheader(name, value)
            conn.endheaders()
        else:
            conn.request('GET', path, headers=headers or {})
        resp = conn.getresponse()
        return resp.status, dict(resp.getheaders()), resp.read()
    finally:
        conn.close()

def main():

            continue
        if path.is_symlink() or not path.is_file():
            fail(f'non-regular or symlinked entry: {path.relative_to(ROOT)}')
        rel = path.relative_to(ROOT).as_posix()
        actual.add(rel)
        if path.name in BAD_NAMES or path.suffix.lower() in BAD_SUFFIXES:
            fail(f'private/credential-like file is not allowed: {rel}')
        data = path.read_bytes()
        # This scanner necessarily contains its own private-key detection regex.
        if rel != 'verify_bundle.py' and (PRIVATE_KEY.search(data) or GH_TOKEN.search(data) or SECRET_ASSIGNMENT.search(data)):
            fail(f'credential-shaped content found: {rel}')
    if actual != REQUIRED:
        fail('unexpected/missing files; unexpected=' + repr(sorted(actual-REQUIRED)) + ' missing=' + repr(sorted(REQUIRED-actual)))

    payload_override=(ROOT/'compose.payload-lab.override.yml').read_text()

    for line in sample.splitlines():

            fail('environment sample contains a non-placeholder value')
