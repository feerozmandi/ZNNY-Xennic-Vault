## ۴. مرحلهٔ B — پایگاه‌داده و ابزار میدانی

```bash
T=~/ZNNY-Xennic-Vault/iee1405-field-toolkit
D=~/xennic-data/barghpa-26-iee1405

# ۱) آزمایشی — هیچ نوشتنی
python3 $T/import_barghpa.py --src $D/raw --db $D/db/barghpa_iee1405.sqlite --dry-run

# ۲) نوشتن (پیش از نوشتن خودکار پشتیبان می‌گیرد)
python3 $T/import_barghpa.py --src $D/raw --db $D/db/barghpa_iee1405.sqlite --write

# ۳) ساخت ابزار میدانی آفلاین
python3 $T/build_html.py --db $D/db/barghpa_iee1405.sqlite --out $D/exports/field

# ۴) آزمون پذیرش روی دادهٔ واقعی
python3 $T/test_toolkit.py
```

### ثبت بازدید سر میز

در HTML هر سالن، فرم پایین هر کارت. تعامل در حافظهٔ همان گوشی می‌ماند
(`localStorage`). پایان روز: دکمهٔ «خروجی JSON تعامل‌ها» → فایل در
`~/Downloads/`. سپس از سرور:

```bash
python3 $T/log_interaction.py --db $D/db/barghpa_iee1405.sqlite \
  --import ~/xennic-data/barghpa-26-iee1405/imports/interactions-<تاریخ>.json
```

### اقدام‌های بعدی

```bash
python3 $T/log_interaction.py --db $D/db/barghpa_iee1405.sqlite --due-list
python3 $T/log_interaction.py --db $D/db/barghpa_iee1405.sqlite --export $D/exports/interactions.csv
```

## ۵. تضمین‌هایی که آزمون شده‌اند

`test_toolkit.py` روی دادهٔ ساختگی با همان ساختار ۵ شیت اجرا می‌شود:
**۴۹ بررسی موفق / ۰ ناموفق**.

| # | تضمین | نحوهٔ سنجش |
|---|---|---|
| D1 | اعداد با تعریف، نه ادعا | بازشماری مستقل + تطبیق با ادعای گزارش |
| D2 | مهاجرت نسخه‌دار و تغییرناپذیر | checksum هر مهاجرت؛ تغییر فایل اجراشده خطا می‌دهد |
| D3 | ایمپورت تکرارپذیر | اجرای دوم: صفر ردیف جدید در شرکت/تماس/شاهد/مشارکت |
| D3 | یادداشت دستی محفوظ | `UPDATE company SET notes` پیش از ایمپورت دوم |
| D3 | شاهد برای هر مقدار | هر `contact` دست‌کم یک `contact_evidence` با منبع و تاریخ |
| D3 | بدون غرفهٔ ساختگی | `participation.booth` برای همه NULL |
| D3 | اولویت بی‌دلیل ممنوع | `priority>0 ⇒ priority_reason` غیرخالی |
| D4 | جست‌وجوی فارسی | ي/ك عربی، نیم‌فاصله، ارقام فارسی/لاتین |
| D5 | سلامت و بازیابی | `integrity_check=ok`، `foreign_key_check=0`، بازگردانی از پشتیبان |
| D6 | ابزار میدانی | صفحه به تفکیک سالن، بدون CDN، `tel:`/`mailto:`، چاپ A4 |
| D6 | ثبت تعامل | ثبت، صدور CSV، ورود JSON، بی‌اثر بودن ورود دوباره |

## ۶. سیاست پشتیبان

- پیش از **هر** ایمپورت: `backups/barghpa_iee1405.<UTC>.pre-import.sqlite`
  با `sqlite3.Connection.backup()` — نه `cp` (کپی از پایگاه باز فایل خراب می‌دهد).
- روزانه (پیشنهاد کرون، ۷ نسخه):
  `0 2 * * * python3 ~/ZNNY-Xennic-Vault/iee1405-field-toolkit/backup_daily.py`
  — یا دستی با `log_interaction.py` بدون نیاز؛ جزئیات در `PRJ-IEE-015 §ابزار`.
- بازگردانی: فایل پشتیبان را روی `db/barghpa_iee1405.sqlite` کپی کنید و
  `integrity_check` بگیرید. آزمون D5.4 همین مسیر را پوشش می‌دهد.

`journal_mode=DELETE` و `synchronous=FULL` انتخاب شده‌اند چون فایل روی پوشهٔ
همگام‌شده می‌نشیند و `WAL` با همگام‌سازی فایل ناسازگار است.
